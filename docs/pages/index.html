Data Analytics Pipeline

Demo output, rebuilt by CI on every push to main. The pipeline generated its own synthetic dataset — 10 runs across 4 conditions — and then analysed it. No real data is involved anywhere on this page.

The input format is the project's own: schema.py is the specification and the bundled generator is its reference producer, so a clone can run the whole thing with nothing to download. The metric set is not fixed by the pipeline either — each file declares its own metrics and the run discovers them.

The report → One self-contained HTML file, organised as seven tabs around the questions it answers. Its findings, figures and tables are computed from the data; four clearly labelled AI interpretations sit beside them. The source on GitHub → Python, Polars end to end. The README covers the architecture and the design decisions behind it.

AI interpretations in the report

Before publishing, CI asks a language model (openai/gpt-oss-120b on GroqCloud) four fixed research questions. Each question is given only the statistical tables that bear on it, and its answer appears in that question’s tab, in a box headed Groq AI interpretation:

  • Conditions — which conditions differ, on what, and how confidently?
  • Reproducibility — would these differences reproduce?
  • Relationships — what relates to the outcome metric, and does it hold inside a run?
  • Multivariable model — what does the multivariable model add?

What is checked. Every answer must cite its evidence as a table, a row and the numbers in it, and each cited number is compared with the cell it names. An answer that cites a wrong number, a missing value or a table outside its question is sent back with the reason, and the site is only republished when all four answers pass. Each answer lists its limitations, and automated review flags common over-claims beside it.

What is not checked. The reasoning. A correctly copied number can still be misread, so the interpretations are a starting point for reading the results, not a conclusion. Where an AI box and the report’s own findings disagree, the findings — computed directly from the data — are the ones to trust.

Ask your own assistant

Every run also writes the two files behind those answers in full, so you can put your own questions to whichever assistant you use. evidence_pack.json holds every derived statistic, with filesystem paths stripped and run identifiers pseudonymised; prompt.md is the briefing that explains what the numbers mean and which conclusions they will not support.

  1. Download prompt.md and evidence_pack.json.
  2. Attach both to a conversation with ChatGPT, Claude or another assistant. Attach them as files rather than pasting: the pack is large.
  3. Ask for an interpretation, or ask something specific. The briefing tells the assistant how to read the evidence, and the pack includes a table of exactly which metrics this run carried.

The briefing matters because several conclusions that look natural are not supported by this kind of data: a large p-value does not establish equivalence, a pooled correlation is not evidence of a relationship, and an association with signal-to-noise does not mean that raising it would raise the outcome. Without those rules stated next to the numbers, a capable reader — human or model — tends to make exactly these mistakes.
